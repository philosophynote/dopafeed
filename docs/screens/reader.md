# Reader（Unit 5c #43、5d #50、要約 #85。#97 で Main からは来なくなった）

## 目的
「無限供給」と「報酬距離」を担う。記事のカードを 1 枚ずつ並べ、「記事を開く」で元サイトを見た目のままアプリ内ブラウザ（シート）に開く。閉じて戻るとその場で判定の区切り（手に入れたカード）を挟み、下に次の未読のカードを継ぎ足す。
閉じるまで読み続けられる流れにしつつ、区切りごとにカードと今日のゴールを見せて、止まり所（DailyGoal）を見失わせない。XP は無い（#106、ADR 0020）。
モックには無い画面。nao の決定で足した（2026-11-03「情報元に遷移せずに無限スクロールで記事を読みたい」ADR 0010、2026-11-04「読みづらい。アプリ内ブラウザのように読みたい」ADR 0011）。

## 要素
上から順。出典: 固定 / DB / dopamine.yml の鍵。

1. ヘッダ（上に貼り付く）: 「閉じる」（→ Main）、「DopaFeed」ロゴ（固定）
2. 記事のカード（1 本ずつ白いカード）
   - OGP 画像（DB: image_url。あればカードの上端に 1.91:1 で全幅、無い・読めなければ出さない。#87、ADR 0016）
   - フィード名・相対時刻・見出し（DB）
   - 枠の帯（DB: readings.tier。段は `cards.rarities`。Main の広げた欄と同じ `readings/_rarity_band`）。判定が届くまでは「判定中 ・ 中身で枠が決まる」で段のリールが回り続け、届くと止まって「24 点 レア ・ 完読でレアカード」（点は 6 軸の合計。ADR 0024・0026）。判定の無いまま一番下の段に決まった記事は「判定できず ノーマル ・ 完読でノーマルカード」。枠と判定の段が食い違う間（枠が決まった後に判定が届いた、境界を変えた）は点も「判定できず」も添えず、段だけ出す
   - 「Claude の 3 行要約」（DB: summary）。本文は描かない。要約は「読む」を押してから作る（ADR 0015）ので、出来るまでは「要約を作成中…」、出来るとその欄だけ差し替わる（Turbo Stream）。失敗なら「要約できませんでした。記事を開いて読めます」、その日の上限（`claude.daily_call_limit`）なら「今日の要約の上限に達しました。記事を開いて読めます」
   - コメントの欄（#197）。Main の広げた欄と同じ `comments/_box` を要約の下に出す。中身・押したときの動き・上限・失敗は comments.md。yml の `comments.*` の鍵が揃わないか有効な人物が 0 人なら出さない
   - 「記事を開く」（橙の大きなボタン。元サイトを別窓で開く。iPhone のホーム画面アプリではシート）
3. 「読み終えた」ボタン。「記事を開く」を押すまで隠す（JS が無いときは最初から見える）。判定が済むと区切りに置き換わる
4. 区切り（判定）: 完読なら枠の色（頂点の SS レアは金色、ほかは橙）で「読了 ・ 24 点」「レアカードを手に入れた！」（判定中なら「読了 ・ 判定中」「カードを手に入れた！」と破線の枠のカード。届いたら見出しとカードを差し替える。判定できなかった記事は「読了 ・ 判定できず」）、手に入れたカード（`cards/_card`。判定した直後の応答では裏（ロゴ）から表へめくれる。長さは `cards.reveal_duration_ms`。頂点はさらに全画面で開封し、どこを押しても Escape でも閉じる。再読込の描き直しではめくらず全画面も出さない。`prefers-reduced-motion` なら表のまま出す。#106 23c）、6 軸のレーダー（判定済みの記事だけ。白い地に 6 角形の図、軸ごとに名前と 1〜5 の点、下に「合計 24 点」。`judgments/_radar`、サーバーが描く SVG。判定中のまま完読したら、届いた時に差し込む。枠と判定の段が食い違うときは「合計 24 点 ・ 付け直すとレア」。#134）、「滞在 X ・ n 本連続」、未完なら灰で「カードにならなかった」「滞在 X。S 秒以上読むと手に入る」（S = `read.complete_after_seconds`）。どちらも「今日のゴール n / 5 ・ あと m 本で宝箱」（`daily_goal.articles`）。完読数がちょうど 5 本目の区切りには金色の「宝箱を開く」（→ DailyGoal。Unit 7 #55）。判定した直後だけ効果音: 完読は見せ場の段に応じた音（下の「区切りの見せ場」。見せ場が無ければめくりの音）、未完は柔らかい煙の音、頂点の全画面ではファンファーレだけ（#100、ADR 0022）
   - 見せ場（#100 22b、ADR 0022。判定した直後だけ。再読込や履歴で戻った描き直しでは出さない）: 区切りの上に、起きたことのうち一番大きい 1 つを大きく出し、残りは 1 行に畳む（入りきらなければ末尾を省く）。押すと動きだけが止まり、文字は残る。判定はサーバー（`CardHighlights`）
     - 特大: 「NEW RECORD! n 連続」（今日の連続が過去の最長を初めて超えた。過去の最長が `cards.record_floor`（2）以上のときだけ。鍵が無ければ出さない）、「SS レアカード！」（一番上の段）。欄の中で火花が散り、ファンファーレ
     - 大: 「COMEBACK!」（昨日 0 本で、それより前にカードがある日の 1 枚目）、「取り返した！」（同じ読書日の直前の判定が未完）、「NEW FEED!」（そのフィードで初めてのカード）、「FIRST CARD!」（今日の 1 枚目）。上がっていく和音
     - 中: 「n 連続！」。`cards.fever_combo` 本に届いたら「FEVER! n 連続」を虹色で出す（鍵が無ければ出さない）。連続が伸びるほど音が半音ずつ上がる
     - 小: 何も出さず、めくりの音だけ
     - 未完: 小さな煙が上がり、柔らかい音。責める文言は出さない
     - 金の全画面の開封では、金以外の見せ場を見出しの下に 1 行で畳む
5. 次の記事のカード（2. と同じ形）。未読が尽きたら「全部読んだ。」と「閉じる」

## 遷移
- Saved の未読の行・宝箱の「もう 1 本だけ」→ 「読む」の POST が 303 で Reader へ（`GET /articles/:id/read`、full page。モーダルは挟まない。#134、ADR 0026）。Main の行は下に広がり Reader へは来ない（#97、ADR 0019）
- Saved の読んだ行 → Reader（枠は変わらない）
- JS が無いとき: 「読む」の POST が直接 Reader へ redirect
- Reader の中: 「記事を開く」→ 元サイトが別窓（シート）で開き、Stimulus `sheet` が `POST /readings/:id/start` で開いた時刻を記録 → シートを閉じて戻る（`visibilitychange` で隠れた後に、見えるか `focus` が戻る。押した瞬間の blur → focus では送らない）か「読み終えた」を押す → `POST /readings/:id/advance` → Turbo Stream で「読み終えた」を区切りに replace、次のカードを `#reader` に append。JS が無ければ次の記事の Reader へ redirect
- Reader → Main（「閉じる」）。完読したカードは消える

## 受け入れ条件（Given-When-Then）
- Given Saved の未読の行か宝箱の「もう 1 本だけ」 When 「読む」を押す Then モーダルを挟まずに Reader が開き、記事のカード（見出し・枠の帯・3 行要約・「記事を開く」）が出る。本文は描かれない（#134、ADR 0026）
- Given 判定を待っている記事の Reader When カードが現れる Then 帯は「判定中」で段のリールが回り続ける。動きを減らす設定ならリールは出さない（#134、ADR 0026）
- Given 判定中の帯 When 判定が届く Then 帯のリールが段を 2 周して止まり、合計点と段が出る。止まった瞬間にレア・S レアは rare、SS レアは gold が 1 回鳴り（ノーマルは無音）、SS レアは金の光が走ってコインが降る。再読込・開き直し・履歴で戻った画面では回らず鳴らない（#134）
- Given 接続の前や切断中に判定が届いた When 接続が戻る Then 帯が枠を取り直して同じように止まり、購読を外す。判定中のまま完読していたら、区切りの見出しとカードも届いた段に替わる（#134）
- Given 判定できない記事（本文なし・失敗・予算切れ・拒否） When 判定が終わる Then 帯は「判定できず ノーマル」で止まる。待たせ続けない（#134）
- Given 判定中のまま完読した When 判定が届く Then 区切りの見出しとカードの枠が届いた段に替わり、6 軸のレーダーが差し込まれる（切断中に届いた分は、接続が戻った時の帯の取り直しが運ぶ）。頂点でも全画面は出さない（#134）
- Given 判定済みの記事 When 完読して戻る Then 区切りのカードの下に 6 軸のレーダーが出て、軸ごとの名前と点、合計が読める。読み上げには「独自性 4、深掘り 3、…」がまとめて渡る。判定できなかった記事と未完の区切りには出ない（#134）
- Given 判定済みで頂点の段の記事 When Reader が開く Then 読む前の全画面は出ない（帯が金になるだけ。全画面は完読の区切りの開封）（#134）
- Given 合計点 When 段を決める Then `cards.rarities` の `min_total` が合計以下の段のうち一番上（今の yml なら 20 点からレア、25 点から S レア、28 点から SS レア）（#134）
- Given 枠の決まった記事 When もう一度「読む」 Then 行は 1 つのまま、枠は変わらない。境界を後で変えても変わらず、付け直すのは `judgments:regrade[apply]` だけ（ADR 0006・0026）
- Given Reader のカード When 「記事を開く」を押す Then 元サイトが別窓（iPhone のホーム画面アプリではシート）で開き、滞在はこの時刻から数える
- Given 記事を開いて complete_after_seconds 以上たった When Reader に戻る Then 区切りに「〜カードを手に入れた！」と、裏からめくれて表になるカードが出て、下に次の未読（published_at が古い方の 1 本）のカードが継ぎ足される（#106）
- Given 頂点の段（SS レア）に決まった記事 When 完読して戻る Then 区切りの上に全画面の開封（「SS レアカードを手に入れた！」とカード）が重なり、どこを押しても閉じる。閉じた後も区切りのカードは残る（#106）
- Given 判定済みの区切り When Reader を再読込する Then カードは表のまま出て、めくり直さず全画面も出ない（#106）
- Given 区切りを見た後に Main へ移った When 履歴で Reader に戻る Then カードは表のまま出て、めくり直さない（#106）
- Given 金の全画面 When 開く Then 「閉じる」に焦点が移り、Tab で後ろへ抜けず、Escape でも背景のどこを押しても閉じ、焦点は区切りへ戻る（#106）
- Given prefers-reduced-motion When 完読して戻る Then カードはめくらずに表で出る（#106）
- Given 今日の 1 枚目で、そのフィードでも初めて When 完読して戻る Then 区切りに「NEW FEED!」が大きく、下に「FIRST CARD!」が 1 行で出る。押すと動きが止まり、文字は残る（#100）
- Given 頂点の段で、今日の連続が過去の最長を超える When 完読して戻る Then 全画面の開封に「NEW RECORD! n 連続 ・ n 連続！」が畳まれ、閉じると区切りの見せ場は NEW RECORD が先頭（#100）
- Given 判定済みの区切り When 再読込する Then 見せ場は出ない（#100）
- Given 記事を開いてすぐ戻った When Reader に戻る Then 区切りは「カードにならなかった」で、記事は Main に未読のまま残る（コンボは途切れる）
- Given 戻りの合図が来ない端末 When 記事を開いた後に「読み終えた」を押す Then 同じ判定になる
- Given 「記事を開く」を押していない When Reader を見る Then 「読み終えた」は出ていない
- Given 古い方の未読が無い When 記事を開いて戻る Then 「全部読んだ。」と「閉じる」が出る
- Given 判定が済んだ記事 When Reader を再読込する Then ボタンの代わりに区切りが出て、二度判定しない
- Given 判定が済んだ記事 When もう一度「記事を開く」を押す Then 滞在は書き換わらない
- Given 「読む」を押していない記事 When `/articles/:id/read` を開く Then Main へ戻る
- Given 記事に OGP 画像がある When Reader のカードを見る Then カードの上端に横長の画像が出る
- Given 要約の無い記事 When 「読む」を押す Then 要約の Job が積まれ、カードに「要約を作成中…」が出る。Job が書き終えると、再読込せずに要約が出る
- Given 要約の無い次の記事 When 読み終えて次のカードが継ぎ足される Then その記事の要約の Job も積まれる
- Given 要約済みの記事 When もう一度「読む」を押す Then Job は積まれず、保存済みの要約が出る（払うのは 1 回）
- Given 要約に失敗した記事・その日の上限 When カードを見る Then その旨が出て、「記事を開く」はそのまま使える
- Given 本文取得がまだの記事 When 「読む」を押す Then 「作成中」のまま待ち、本文取得を試し終えたら要約の Job が積まれる
- Given 「読む」を押していない記事 When 新しい記事が取り込まれる Then 要約は作られない（API を呼ばない）
- Given コメントの鍵が揃い有効な人物がいる When Saved の行（未読でも読んだ行でも）から Reader が開く Then 要約の下、「記事を開く」の上にコメントの欄が出る。作成済みならその組のカードが出る（#197）
- Given Reader のコメントの欄 When 「コメントを見る」を押す Then 画面を移らずに欄の中でカードが「書いています…」で出て、書けた人から本文に変わる（Main と同じ。#197）
- Given コメントの鍵が揃っている When 読み終えて次の記事のカードが継ぎ足される Then そのカードにもその記事のコメントの欄が出る（#197）
- Given コメントの鍵が欠けている、または有効な人物が 0 人 When Reader を開く Then コメントの欄は出ない（#197）

## 使う設定の鍵
dopamine.yml: `read.complete_after_seconds`, `claude.daily_call_limit`, `cards.rarities`, `cards.reveal_duration_ms`（区切りのカードのめくり）, `cards.fever_combo`（FEVER になる連続の本数。#100）, `cards.record_floor`（NEW RECORD と呼ぶ過去の最長の下限。#100）, `daily_goal.articles`
personas.yml: なし

## 外部 API
Claude（要約。「読む」と継ぎ足しのときに `Claude::SummarizeArticleJob` を積み、画面は待つだけ。ADR 0015）。コメントは押したときだけ xAI の Grok（comments.md。ADR 0029・0034）。元サイトは端末のブラウザが直接開く
