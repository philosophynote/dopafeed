# Swipe（左スワイプの「興味なし」は Unit 8a #56。一掃・「もう一度読む」・学習は第二の陣）

## 目的
無限供給と FOMO の裏側。未読が積もったときの「逃げ道」を用意し、罪悪感をリセットする。
左スワイプの「興味なし」でフィードと単語の重みを下げ、古い未読は一掃して「もう一度読む」として、たまに再提示する。

## 要素
1. 一掃バナー（橙）: 「未読が 112 本に。2 週間より古い 64 本を一掃しますか？」、注記、ボタン「64 本を一掃 ＋20 XP」「あとで」（本数・日数・XP は未決 1）
2. スワイプ中のカード: 右側に灰色の「興味なし」レール、カードが左に 118px ずれている。カード内に「このフィードの『政治・ビジネス』系は読了率 4% です」「左スワイプで『興味なし』→ フィードと単語の重みを下げる」（DB: フィード重み、タグ別読了率）
3. 「もう一度読む ・ 先月いいねした記事」カード（薄く表示。ボタン「読み返す ＋5 XP」。未決 2）
4. 通常カード、タブバー（Main と同じ）

## 遷移
- Main 内の操作（別画面ではない。Main の状態の一つ）
- 左スワイプ、またはカードの「興味なし」ボタン → `POST /articles/:id/dismissal` → Turbo Stream でカードを「「見出し」を興味なしにした ・ 元に戻す」の帯に替え、未読数（ステータスカード・タブバー）を合わせる。重みの更新は第二の陣（ADR 0012）
- 「元に戻す」→ `DELETE /articles/:id/dismissal` → 帯がカードに戻る。帯は Main を開き直すと出ない
- 右スワイプ → 何もしない（指を離すとカードが戻る。ADR 0012）
- 「一掃」→ 対象記事を archived に（Main に戻る）
- 「読み返す」→ Roulette

## 受け入れ条件（Given-When-Then）
- Given 2 週間より古い未読が 64 本 When Main を開く Then 一掃バナーに 64 本と出る
- Given 一掃を押した When 完了 Then 64 本が一覧から消え、archived として残る（+20 XP は鍵 `sweep.xp` が入ったら）
- Given カードを左スワイプ When 離す Then カードが消え、そのフィードの重みが下がる（学習は Learning の節。第二の陣）
- Given 未読のカード When 「興味なし」を押す（左スワイプで離す）Then カードが「元に戻す」の帯に替わり、未読数が 1 減り、`articles.dismissed_at` が入る。XP・読了・今日のゴール・コンボ・ストリークは変わらない
- Given 「興味なし」にした帯 When 「元に戻す」を押す Then カードが戻り、未読数が 1 増え、`dismissed_at` が nil になる
- Given 「読む」で開いたが未完の記事 When 興味なしにする Then カードは消えるが Reading（出目・滞在）は残る。開いたままの Reader で読み終えれば完読になる（ADR 0012）
- Given 興味なしにした記事 When Reader で前の記事を読み終える Then 次の 1 本に継ぎ足されない
- Given Main を開き直す When 興味なしにした記事がある Then カードも帯も出ない
- Given JS が無い When 「興味なし」を押す Then Main に戻り、カードは消えている

personas.yml: なし

2. 「もう一度読む」の抽出条件（いいね済み・N 日経過）と再提示の頻度、+5 XP
3. スワイプのジェスチャー実装（Stimulus で touch 系。PWA 内の横スワイプが iOS の戻るジェスチャーと競合しないか）
    → **決定（Unit 8a、#56）**: Pointer Events の Stimulus `swipe`（touch 固有 API は使わない）。画面の左端（OS の「戻る」の帯）から始まった触りと、ボタン・リンクの上から始まった触りは拾わない。横の動きが縦より大きくなってから横と決め、縦ならスクロールに任せる（`touch-action: pan-y`）。閾値（カード幅の 4 割）は操作の寸法として JS に置く（yml の鍵にするかは 8a-2 の PR 本文で提案）。スワイプは「興味なし」の form を送るだけで、Mac と JS 無しは同じボタンを押す。実機での手触りは nao が確かめる
4. 興味なしの学習先（フィード単位 + タグ単位。タグをどう抽出するか）
    → **決定（Unit 8a、#56）**: この Unit では学習しない。`articles.dismissed_at` を材料に残すだけ（ADR 0012）
5. 右スワイプを何に充てるか
    → **決定（Unit 8a、#56）**: 何もしない。Saved 画面の Unit で「保存」に充てる（ADR 0012）
6. 続けざまに別のカードを「興味なし」にすると、Turbo が先の送信を止めて応答を捨て、先のカードが画面に残る（サーバーには入っている。未読数だけ減る）。もう一度押せば帯に替わる。8a-2 のスワイプでは送信中は次のスワイプを待たせるか、戻ってきた応答で前のカードも片付けるか
    → **決定（Unit 8a-2、#56）**: スワイプの送信は 1 本の列に並べ、前の `turbo:submit-end` を待ってから送る。応答が来ないまま 10 秒過ぎたら送れなかった扱いでカードを戻し、途中で画面を離れたら列だけ進める（戻るカードは無い）。ボタンの連打は 8a-1 のまま（もう一度押せば帯に替わる）
