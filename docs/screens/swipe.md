# Swipe（左スワイプの「興味なし」は Unit 8a #56、右スワイプの「保存」は Unit 20 #95。一掃・「もう一度読む」・学習は第二の陣）

## 目的
無限供給と FOMO の裏側。未読が積もったときの「逃げ道」を用意し、罪悪感をリセットする。
左スワイプの「興味なし」でフィードと単語の重みを下げ、古い未読は一掃して「もう一度読む」として、たまに再提示する。

## 要素
1. 一掃バナー（橙）: 「未読が 112 本に。2 週間より古い 64 本を一掃しますか？」、注記、ボタン「64 本を一掃」「あとで」（本数・日数は未決 1。モックの「＋20 XP」は ADR 0020 で数値の報酬をやめたので出さない）
2. スワイプ中のカード: 右側に灰色の「興味なし」レール、カードが左に 118px ずれている。カード内に「このフィードの『政治・ビジネス』系は読了率 4% です」「左スワイプで『興味なし』→ フィードと単語の重みを下げる」（DB: フィード重み、タグ別読了率）
3. 「もう一度読む ・ 先月いいねした記事」カード（薄く表示。ボタン「読み返す」。モックの「＋5 XP」は出さない（ADR 0020）。未決 2）
4. 通常カード、タブバー（Main と同じ）
5. 効果音（#100、ADR 0021）: 1 回の引きで最初に閾値を越えた瞬間に 1 回（Main・Saved の行も同じ）。同じ指で戻して越え直しても、離して流れ出す間や戻る間にも鳴らない

## 遷移
- Main 内の操作（別画面ではない。Main の状態の一つ）
- 左スワイプ → 行の中の隠れた「興味なし」の form を送る → `POST /articles/:id/dismissal`（見えるボタンは無い。#91） → Turbo Stream で行を隠し（同じ id の中身の無い li を残して位置を覚える）、画面下（タブバーの上）に暗いトースト「1 件を削除しました　元に戻す」を出し、未読数（タブバーとアイコンのバッジ）を合わせる。重みの更新は第二の陣（ADR 0012）
- トーストの「元に戻す」→ `DELETE /articles/:id/dismissal` → 行が元の位置に戻り、トーストが消える。トーストは `toast.visible_seconds` 経つと消え（鍵が無ければ次のトーストか画面の移動まで残る）、続けて引くと後のものに置き換わる。隠した行は Main を開き直すと出ない（#112）
- 右スワイプ → 「保存」（あとで読む）。引いた幅だけ左から背景とブックマークのアイコンが伸び、閾値の手前は灰、越えたら橙。行の中の隠れた form を送る → `POST /articles/:id/bookmark`（Unit 20、ADR 0018。docs/screens/saved.md）
- 「一掃」→ 対象記事を archived に（Main に戻る）
- 「読み返す」→ Roulette

## 受け入れ条件（Given-When-Then）
- Given 2 週間より古い未読が 64 本 When Main を開く Then 一掃バナーに 64 本と出る
- Given 一掃を押した When 完了 Then 64 本が一覧から消え、archived として残る（報酬は付けない。ADR 0020）
- Given カードを左スワイプ When 離す Then カードが消え、そのフィードの重みが下がる（学習は Learning の節。第二の陣）
- Given 未読の行 When 左スワイプで離す Then 行が消えて画面下に「元に戻す」のトーストが出て、未読数が 1 減り、`articles.dismissed_at` が入る。カード・読了・今日のゴール・コンボ・ストリークは変わらない
- Given 「興味なし」にした直後のトースト When 「元に戻す」を押す Then 行が元の位置に戻ってトーストが消え、未読数が 1 増え、`dismissed_at` が nil になる
- Given 「読む」で開いたが未完の記事 When 興味なしにする Then カードは消えるが Reading（出目・滞在）は残る。開いたままの Reader で読み終えれば完読になる（ADR 0012）
- Given 興味なしにした記事 When Reader で前の記事を読み終える Then 次の 1 本に継ぎ足されない
- Given Main を開き直す When 興味なしにした記事がある Then 行もトーストも出ない
- Given 行全体は「読む」のボタン When その上から左へ引いて閾値に届かずに離す Then 行は戻り、読みにも進まない（引いた後の click を読みにしない。#91）
- Given yml に `swipe.flick_velocity` と `swipe.flick_window_ms` がある When 閾値の手前でも、離す直前のその長さの間、引いた向きへその速さ（px/ms）より速く払って離す Then 閾値まで引いたのと同じに流れて片付く。ゆっくり引いて離す・止めてから離す・離す直前に戻す・`swipe.flick_min_px` に届かない滑りは戻る。鍵が無ければ払いでは片付かない（#112）
- Given 行を引いている途中 When iOS が指を取り上げる（`pointercancel`） Then 閾値を越えていれば片付き、手前なら払っていても戻る（取り上げは縦のスクロールなど払うつもりでない指にも来る。#112）

## 使う設定の鍵
dopamine.yml: `swipe.dismiss_threshold_ratio`、`swipe.flick_velocity`（払いと見なす速さ。#112）、`swipe.flick_window_ms`（速さを測る離す直前の長さ。この二つが無ければ払いでは片付けない）、`swipe.flick_min_px`（払いでも要る引いた幅。少し滑ったタップを払いにしない）、`swipe.submit_timeout_seconds`、`toast.visible_seconds`（取り消しのトーストが消えるまで。#112）。一掃の閾値（本数・日数）は鍵が無い（未決 1, 2）
personas.yml: なし

## 未決
1. 一掃の閾値（未読 N 本以上、M 週間より古い）。提案: `sweep.threshold_unread: 100`, `sweep.older_than_days: 14`（モックの +20 XP は ADR 0020 で落とした）
2. 「もう一度読む」の抽出条件（いいね済み・N 日経過）と再提示の頻度
3. スワイプのジェスチャー実装（Stimulus で touch 系。PWA 内の横スワイプが iOS の戻るジェスチャーと競合しないか）
    → **決定（Unit 8a、#56）**: Pointer Events の Stimulus `swipe`（touch 固有 API は使わない）。画面の左端（OS の「戻る」の帯）から始まった触りと、ボタン・リンクの上から始まった触りは拾わない。横の動きが縦より大きくなってから横と決め、縦ならスクロールに任せる（`touch-action: pan-y`）。閾値は `swipe.dismiss_threshold_ratio`（カード幅に対する比）として dopamine.yml に置き、view が Stimulus の value で渡す（8a-2 で nao の許しを得て鍵を足した）。スワイプは「興味なし」の form を送るだけで、Mac と JS 無しは同じボタンを押す。実機での手触りは nao が確かめる
    → **改め（#91）**: 「興味なし」の見えるボタンは消し、左スワイプだけにする（Mac もマウスで引ける。JS 無しでは興味なしにできない）。行全体が「読む」のボタンなので、そのボタンの上から始まった触りも拾い、横へ引いた後の click は読みにしない。読む送信も同じ列に並べる
    → **改め（#91、nao 2026-11-07「Gmail のようにアイコンが出る形式で、興味なしは『削除』に」）**: 画面の呼び名を「削除」にする（引いた背景・取り消しの表示）。記録は今まで通り `articles.dismissed_at` で、「元に戻す」で戻せる（購読の削除と違い消えない）。引いた幅だけ右から丸型の背景とゴミ箱のアイコンが伸び、閾値の手前は灰、越えたら赤。行は傾けずに平らに滑らせる。
    → **改め（#112、nao 2026-11-10「削除に至るまでのプロセスを長くとっているので誤削除は起きにくい。画面下部に表示を出す方法で」）**: 行の場所に残していた「「…」を削除した ・ 元に戻す」の帯をやめ、行は消して画面下（タブバーの上）に Gmail 風のトースト「1 件を削除しました　元に戻す」を出す。保存・保存を外すも同じ形に揃える（saved.md）
    失うもの: 削除はスワイプだけになり、キーボードと VoiceOver からは実行できない（一人用で nao は指かマウスで引ける。要るなら VoiceOver のカスタムアクションを別に足す）
4. 興味なしの学習先（フィード単位 + タグ単位。タグをどう抽出するか）
    → **決定（Unit 8a、#56）**: この Unit では学習しない。`articles.dismissed_at` を材料に残すだけ（ADR 0012）
5. 右スワイプを何に充てるか
    → **決定（Unit 8a、#56）**: 何もしない。Saved 画面の Unit で「保存」に充てる（ADR 0012）
    → **決定（Unit 20、#95）**: 「保存」（あとで読む）。保存した記事は Main から退き Saved に移る（ADR 0018）
6. 続けざまに別のカードを「興味なし」にすると、Turbo が先の送信を止めて応答を捨て、先のカードが画面に残る（サーバーには入っている。未読数だけ減る）。もう一度押せば片付く。8a-2 のスワイプでは送信中は次のスワイプを待たせるか、戻ってきた応答で前のカードも片付けるか
    → **決定（Unit 8a-2、#56）**: スワイプの送信は 1 本の列に並べ、前の `turbo:submit-end` を待ってから送る。応答が来ないまま `swipe.submit_timeout_seconds` 過ぎたら送れなかった扱いでカードを戻し、途中で画面を離れたら列だけ進める（戻るカードは無い）。ボタンの連打は 8a-1 のまま（もう一度押せば片付く）
