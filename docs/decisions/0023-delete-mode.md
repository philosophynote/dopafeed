# ADR 0023: Main の削除は左スワイプをやめ、削除モードのボタンで行う
日付: 2026-11-15 状態: 採用（#129）。ADR 0012 の記録（`articles.dismissed_at`）は変えない

nao の決定（2026-11-15「削除方法を変えたい。上部のラジオでモードを切り替え、削除ボタンで記事を削除。削除 1 件を 1 コンボにして、モード終了時に何分で何件削除したかをリザルトで出す」。#129 の計画を決定札で推奨どおり承認）。

- **Main の行の左スワイプは削除しない。** 引いても行は動かず、ゴミ箱の背景も出ない。削除の道を削除モードのボタン 1 本にする。右スワイプの保存（ADR 0018）と、Saved の左スワイプ（保存を外す）はそのまま
- **ヘッダに「読む / 削除」のラジオを置く。** 別の行に置くと一画面に入る行が 1 本減る（#91 の「画像つきの行が 6 本」）ので、ヘッダの行に収め、代わりに「フィードを追加」の文字リンクを「＋」のアイコンにした（読み上げと title は「フィードを追加」のまま）
- **「削除」の間は、行ごとに左端へ赤い丸の削除ボタンを出す。** 押すと今までの隠れた form と同じ `POST /articles/:id/dismissal` を送り、行は消えて画面下のトーストが出る（#112 のまま）。ボタンは行の上端に揃えるので、行が詰まると次の行のボタンが同じ指の下に来て連打できる。押し過ぎはトーストの「元に戻す」で直前の 1 件を戻す
- **送信は行の送信の列（`submission_queue.js`）に並べる。** 連打しても Turbo が前の応答を捨てない（#56 の未決 6、#122 と同じ理由。指で押した submit の配送中に `requestSubmit` しない）
- **「削除」の間は、行のタップで読まず、左右に引いても動かない。** 連打の指が少しずれても読み（抽選と Reading）や保存に化けないようにする。切り替えた瞬間に広げていた欄は畳む
- **モードは画面に残さない。** 再読込・別の画面から戻る・ブラウザの復元では「読む」で始まる（Turbo の写しを取る前に戻す）
- **コンボとリザルトは削除モードの中だけの数で、サーバーに残さない。** カード・今日のゴール・ステータスの「n 連続」・ストリークは動かさない（ADR 0012、削除は読了ではない）。コンボはモードの間は途切れず、元に戻すと 1 減る。数えるのは押した時点（応答で数えると、続けて押してすぐ戻したとき列に並んだ分がリザルトから抜ける）で、送れなかった分は引く。リザルトは「読む」に戻した瞬間に Main の上へ重ね、件数・かかった時間（切り替えてから戻すまで）・1 件あたりの秒数を出す。0 件なら出さない。数字の鍵は足さない
- **失うもの:** 1 本だけ消すのに、切り替え → 押す → 戻すの 3 手が要る（スワイプなら 1 手）。代わりに削除がキーボードと VoiceOver からもできるようになった（swipe.md の未決 3 の「失うもの」が解ける）
- **削除の音はメロディ（26c、2026-11-15 nao が決定札で選択）。** 押すたびに、C メジャー・ペンタトニックで組んだ 16 音のメロディの次の 1 音（コンボ n なら n 音目）を鳴らし、押す間合いをリズムにする。読了の連続の `combo`（半音ずつ上がり 1 オクターブで止まる）は使わない。ビートと判定（BPM・判定幅の鍵が要る）は入れない
- **コンボの節目（2026-11-21 nao が #158 の計画を承認）。** `delete_mode.combo_small_every`（5）の倍数で小、`delete_mode.combo_large_every`（10）の倍数で大の演出を、コンボの帯の中だけに出す（Main に全画面を重ねると一覧が隠れて連打が止まる。ADR 0019）。重なる数では大だけ（ADR 0022 の一番大きい 1 つ）。回の中で届いた一番上の数を超えたときだけ出し、元に戻して届き直しても出し直さない（戻して押すだけで報酬が出るのを防ぐ）。大の後は帯をモードの間ずっと虹にする。文言は「NICE!」「GREAT!!」で、読了の「FEVER」は使わない（削除のコンボは読了の連続と別物）。節目でも `melody` は鳴らし、音を重ねるだけにしてリズムを切らない
- **持ち越し:** 自己ベストと NEW RECORD（回の記録にテーブルが要る）、Saved の削除モード
