# ADR 0036: 流すモード（無限スクロール）では、画面の上へ流れ切った行を削除する
日付: 2026-11-26 状態: 採用（#194）。ADR 0035 の「B を採らない」を、このモードの中だけ改める。読むモード・処理モード、記録（ADR 0012 の `articles.dismissed_at`）、一括片付けの API（ADR 0035）は変えない

nao の依頼（2026-11-26「B 案も面白いから、無限スクロールモードっていうモードを作って、その場合だったら、B 案の通り、スクロール画面から消えたら、削除っていう扱いにしてみて」）。#194 の計画を nao が決定札で「推奨のまま承認」とした。

- **ヘッダのラジオを「読む / 処理 / 流す」の 3 つにする。** 「流す」が無限スクロールモードで、読み上げは「無限スクロール」。6 文字はヘッダに入らないので見える字は 2 文字に揃え、1 つの幅を 56px から 44px（押せる大きさの下限）に詰め、ヘッダの間を 8px から 4px にした。再読込・戻る・別の画面から戻ると「読む」で始まる（開いただけで消え始めないように。処理モードと同じ）
- **消すのは、このモードの間に一度画面に入った行が、下端まで画面の上へ流れ切ったとき。** 見えていた時間は問わない（鍵を足さない。速く払い上げた見出しも消えるが、下の 2 つで戻せる）。入る前に上へ流れていた行は、一度画面に入るまで消さない。広げた行・押して読み始めた行・一覧の中で読み終えた行・払っている行は消さない
- **流れるたびには送らず、スクロールが止まったとき（`scrollend`。iOS Safari 26.2 から）にまとめて `POST /sweep`（`flow=1`）へ送る。** まとまりは止まった時点で締め、応答を待つ間に流れ始めた分は次の止まりまで送らない（1 回のスクロールを複数のトーストに割らない）。`scrollend` の無いブラウザ（`allow_browser :modern` が通す Safari 17.2〜26.1）では、止まりを測る秒数の鍵を足す代わりに、流れた分をすぐ送り、応答を待つ間に流れた分を次にまとめる（トーストは細かく割れる）。 「読む」「処理」へ切り替えたときも送る。計画にあった「最後の行が流れたときにも送る」は持たない（下の余白があるので、最後の行の後もスクロールは止まって `scrollend` が来る）。行の送信と同じ列（`submission_queue`）に並べ、送った回数を付ける（ADR 0035 と同じ理由）。サーバーは今の片付けと同じく未読で絞り直し、送った id と実際に消した id を返す。実際に消した行だけを「送った」にし、別のタブで先に消えていた記事などは薄さを取る（その行の「戻す」で、ほかで付いた削除まで外さない）。待ちの上限を越えた後に届いた結果も行に反映する。送る前に画面を離れた分は消えない（消し損ねる側に倒す）
- **流れた行は抜かずにその場で薄くし、「流した ・ タップで戻す」を重ねる。** 画面の上の行を抜くと、`overflow-anchor` の無い iOS 27 より前の Safari では見ている行が跳ねる。`flow=1` の応答は行を差し替えず、トーストと未読数だけを書き直す。開き直すと出ない。Turbo の写しと bfcache では、届いた薄い行を隠し、届いたか分からない行は未読の見た目に戻す（戻ったときに消えた記事を並べず、消えていない記事を隠さない）。薄い行の中身は inert にし、Tab や VoiceOver で消した記事を読み始めない。「戻す」のボタンは読み上げに記事の見出しを含める
- **元に戻す手段は 2 つ。** トースト「n 件を流しました」の「元に戻す」でひとまとまりを戻す（`DELETE /sweep`）。上へ戻って薄い行をタップすると、その 1 本だけを戻す（`keep_toast=1` で出ているトーストは消さない）。戻した行はこのページにいる間は流し直さず、まだ送っていないまとまりからも外す（一括片付けを戻した行が、Turbo が差し替えた古い行の通知で送信待ちに入り、「読む」へ切り替えたときにまた消えていた。レビュー P1）。`DELETE /sweep` は、まだ消えている記事の行だけを差し替える（先に 1 本ずつ戻した記事の、広げた欄や読み終えた行を壊さない）。送れなかった（圏外など）まとまりは薄さを取って未読のまま残す
- **払った行・片付けた行の「元に戻す」が出ている（または描かれる前の）間に流したら、流した分のトーストは出さない（`keep_toast=1`）。** 払った行・片付けた行は跡に替わりトーストでしか戻せないが、流した行は薄い行のタップで戻せる。押していない流しで、押した操作の取り消しを消さない（レビュー・Codex 指摘）。流しのトーストは「元に戻す」に `flow=1` を持ち、これで見分ける
- **「処理」から「流す」へ切り替えたときも処理のリザルトを出す。** 「読む」を経ずに移ると、出さなければその回のコンボが見えないまま消える。閉じるのは 1 タップ
- **最後まで流し切れるよう、流すモードの間だけ一覧の下に一画面ぶんの余白を足す。** 全部流したら余白の上に「全部流した。」を貼りつける
- **末尾からの戻り道（2026-11-28 追記、#211。nao が決定札で「A + B」を選んだ）:** 余白の上に「先頭に戻る」を貼りつけ、フィードで絞っているときは「次は ◯◯ n 件を流す」も並べる。後者で開いた先だけは流すモードのまま始める（上の「再読込・戻るでは読むで始まる」の例外）。開く先を覚えるのは JS のモジュールの変数だけにし、URL や sessionStorage には持たせない（再読込・戻る・チップでは今どおり読むで始まる）。押したら流した分を送り切ってから開く（送信中に移ると Turbo が送信を止め、流した記事が未読のまま残る）。スクロール中ずっと出る「上へ」ボタンは採らない（常に出すものを増やさない）
- **カード・今日のゴール・ストリーク・処理モードのコンボとリザルトに数えない。音も鳴らさない。** 読まずに流すことを報酬の目当てにしない（ADR 0012・0035）。「残り n 件を片付ける」も流した行を数えず、片付けで送らない
- **一定時間見えた行だけを消す案を採らない理由:** `flow.*` に秒数の鍵が要り、値は nao が決めることになる。まず鍵なしで手触りを確かめる
- **「流した記事」の一覧画面を作らない理由:** docs/screens に無い画面が増える。消した記事は 1 日で自動削除される（ADR 0027）
- **失うもの:** 速く払い上げただけで見出しを読んでいない行も消える。まとまりのトーストは次のまとまりに置き換わるが、薄い行は開き直すまでタップで戻せる。開き直した後は戻す場所が無い。キーボードでは流れない（Tab でたどるとフォーカスに合わせてブラウザがスクロールするが、最後の入力がキーなら流さない。指・マウス・ホイールで動かせばまた流れる）
