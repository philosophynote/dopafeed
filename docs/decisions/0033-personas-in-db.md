# ADR 0033: コメントの人物は DB の personas 表に置き、設定画面から出す・外す・書き換える
日付: 2026-11-23 状態: 採用（#172）。ADR 0029 の「人物は config/personas.yml」と、採らなかった案「人物を DB に置く」を改める。呼び先・1 記事 1 回・日次上限は 0029 のまま

nao の決定（2026-11-23 #172 の計画に「承認」。編集の画面を作るのは nao の選択）。

## 決めたこと
- **人物は `personas` 表が正。** 列は `slug`（一意、英小文字とハイフン）・`name`・`title`・`color`・`description`・`system_prompt`・`enabled`（既定 true）・`position`。人物を外す・戻す・口調を直すのに PR とデプロイを要らなくする
- **初期値は db/seeds/personas.yml。** migration は表が空のときだけ yml の 8 人を並び順で入れる。本番はデプロイだけで揃い、人の手は要らない。入れた後に yml を変えても本番には届かない。schema を読むだけの db:setup に備え、db:seed も空のときだけ同じことをする
- **消さずに外す。** 外した人（`enabled` false）は生成の指示とスキーマに入れず、保存済みのコメントも出さない。コメントは残すので、戻せば過去の記事でもまた出る
- **`persona_comments.persona_id` は文字列のまま `personas.slug` を指す。** 既存のコメントを書き換える migration を要らなくする。外部キーは張らない（モデルの `belongs_to` で存在だけ確かめる）
- **「生成済み」は有効な人のコメントがあるかで決める。** 外した人の分しか無い記事は未生成と同じに扱い、押せば今の有効な人の分を作って足す
- **有効な人物が 0 人なら、コメントの欄を出さない。** Commenter も API を呼ばず台帳も減らさずに失敗にする

## 採らなかった案
- **yml のまま、有効フラグだけ足す**: 外すたびの PR とデプロイが残る
- **`persona_comments` に人物の整数の外部キーを張る**: 既存のコメントを書き換える migration が要り、人物を消すとコメントも道連れになる
- **初期値を migration に直に書く**: 8 人分の長い system_prompt で migration が読めなくなる。yml なら差分が見やすい

## 承知している弱み
- **人物を書き換えても、保存済みのコメントは前の口調のまま。** 作り直しは持ち越し（#174 で人物ごとに作る形になれば足りない人だけ作れる）
- **すでにコメントのある記事では、後から有効にした人は出ない。** 同上
- **人物の変更は PR に履歴が残らない。** 一人用で、戻したければ画面で書き戻す
