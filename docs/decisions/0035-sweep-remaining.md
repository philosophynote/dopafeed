# ADR 0035: 一覧の下の一押しで、並べた未読をまとめて削除する
日付: 2026-11-24 状態: 採用（#189）。記録（ADR 0012 の `articles.dismissed_at`）、1 本ずつの払い（ADR 0030・0032）、自動削除（ADR 0027）は変えない

nao の依頼（2026-11-24「削除することがめんどくさい」）。#189 で 3 案（A 一覧の最後に一括で片付ける / B 流れた行は見ただけで消す / C 未読の保持日数を縮める）を示し、nao が決定札で A を選んだ。

- **Main の一覧の下に「残り n 件を片付ける」。** 読みたい行は先に広げるか右へ払って保存し、最後に一押しで残りを消す。読むモード・処理モードとも出し、見える行が 0 本なら隠す
- **消すのは、その表示で並べた記事のうち、押した時点でまだ未読のものだけ。** 送る id はサーバーが描いた全行で、`POST /sweep` が `Article.unread` で絞り直す。押す前に払った・保存した・完読した記事は外れ、表示の後に届いた新着は id を持たないので消えない。消す記事は同じ時刻で `dismissed_at` を入れる
- **開いたが未完の記事も消す。** 広げて要約を見て要らぬと分かった行こそ消したい。残したい読み途中は保存すれば残る。`Reading` は消さない（ADR 0012 の 1 本ずつの削除と同じ）
- **確かめの dialog は挟まない。** トースト「n 件を片付けました」の「元に戻す」（`DELETE /sweep`、消した記事の id だけ）で全部戻る。ADR 0023 と同じく、確かめの一手より戻せることを選ぶ
- **送信は行のスワイプ・トーストと同じ列（`submission_queue`）に並べ、送った回数を付ける。** 並べずに送ると、応答待ちのスワイプの送信を Turbo が止める。回数は、前の行のトーストの「元に戻す」をこのトーストに置き換わった後で送らせないため
- **払った行が流れている間（`swipe-active`）は、落ち着くまで待ってから列に並べる。** 払った行は流れ切ってから列に並ぶので、先に片付けを並べると、後から届くその行のトーストが片付けのトーストを置き換え、片付けを戻せなくなる。待つのは `swipe.submit_timeout_seconds` まで
- **初めの片付けが書き込めたのに応答が届かず押し直したら、表示の後に消えた記事も行を隠して「元に戻す」に入れる。** 未読で絞るだけだと空の応答になり、行も「元に戻す」も戻らない（Codex 指摘）。表示した時刻（`rendered_at`）をフォームに描き、JS は見えている行の id だけを送る。見えていた行が表示の後に消えているなら、届かなかった片付けの分とみなせる。操作ごとの印を DB に持つ案は、表を足すほどの場面ではないので採らない
- **一覧の中で読み終えた行は数えない。** 行は区切りに替わって残るが未読ではない。数が 0 になったらボタンを隠す
- **カード・今日のゴール・ストリーク・処理モードのコンボとリザルトに数えない。音も鳴らさない。** 消すだけで報酬が出ると、読まずに片付けることが目当てになる（ADR 0012・0023）
- **B を採らない理由:** 見出しを読まずに速くスクロールしただけでも消え、戻す場所（流した記事の一覧）という画面が増える
- **C を採らない理由:** 目の前の山は減らない。日数は `retention.unread_days` で nao がいつでも変えられるので、A と併せて使える
- **失うもの:** 一覧の最後まで見ないうちに押すと、見ていない行も消える（トーストで戻せる）。払った直後に片付けると、その 1 本の「元に戻す」は片付けのトーストに置き換わって押せなくなる（1 本ずつ続けて払ったときと同じ）。消えた記事は 1 日後に自動削除で消える（ADR 0027）
