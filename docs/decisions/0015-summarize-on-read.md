# ADR 0015: 要約は「読む」で行ができた記事だけ作る
日付: 2026-11-07 状態: 採用（#85）

nao の決定（2026-11-07「AI要約は定期実行ではなく、読むボタンをクリックしたら実行されるようにしてください。読まない記事も要約されてしまうのでコストの無駄です」。#85 の計画を推奨どおり承認）。Unit 4（#18）の「10 分ごとの定期 Job が要約待ちを予算いっぱいまで積む」と SPEC の「定期ジョブで Claude で要約する」を覆す。

- **定期の要約 Job（`Claude::SummarizePendingArticlesJob` と recurring.yml の項）は捨てる。** 要約を積むのは Main の「読む」（`ReadingsController#create`）と、Reader が次のカードを継ぎ足すとき（`#advance`）だけ。継ぎ足しのカードも要約が主役なので含める（Reader を閉じると、開かない 1 本ぶんは払う）
- **「読むと決めた」= `readings` に行がある。** 新しい列は足さず `Article.awaiting_summary` に `Reading` の有無を足す。本文取得前の記事は今までどおり要約しない（薄いフィード本文の要約は二度と直らない）。その分は `FetchArticleContentJob` が取得を試し終えたときに積む
- **要約は `articles.summary` に残して使い回す。** Job は要約済み・失敗を記録済みなら呼ばない。積む所が 3 か所になり同じ記事が二度積まれうるので、失敗済みでも呼ばない（失敗のやり直しは人が戻したときだけ。#32）
- **待ち時間は Reader の要約欄に「作成中」を出し、Job が書き終え・失敗・予算切れのたびに Turbo Stream（Solid Cable。Rails 8 の既定で設定済み）で差し替える。** ポーリングはしない（秒数の鍵が要らない）。購読がつながる前に書き終えた差し替えは届かないので、つながるたびに作成中なら `GET /articles/:id/summary` で欄を一度取り直す
- **Main のカードの要約 2 行は、読む前の記事にはほぼ出なくなる（見出しだけ）。** フィード本文の冒頭を代わりに出すかは別に決める
- 費用の上限（`claude.daily_call_limit`）と 1 回の呼び出しの形（ADR 0002、#33）は変えない。dopamine.yml の鍵の追加も無い
