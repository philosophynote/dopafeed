# ADR 0030: 処理モードは削除ボタンをやめ、左へ払えば削除・右へ払えば保存
日付: 2026-11-21 状態: 採用（#159）。ADR 0023 の「削除ボタン」「左スワイプは削除しない」「削除モードの間は左右に引いても動かない」を改める。記録（ADR 0012 の `articles.dismissed_at`、ADR 0018 の `articles.bookmarked_at`）は変えない

nao の依頼（2026-11-21「削除モードの名称を処理モードに。削除ボタンを廃止して、フリックで削除とブックマーク登録」）。計画の向き（右 = 削除）は nao が Issue で「フリックの向きは通常モードと処理モードで揃えて」と改めた。

- **処理モードでは、左へ払うと削除、右へ払うと保存。** 右 = 保存は読むモードと同じ向きで、モードを替えても指の覚えた向きは変わらない。保存は Saved の保存と同じもの（Main・未読数・バッジから外れ、保存タブに並ぶ）
- **読むモードの左は今までどおり動かない。** 削除は処理モードの間だけ。読むつもりの指で消さない（ADR 0023 で左スワイプの削除をやめた理由を守る）。行は `dismissNeedsProcessMode` の値でこれを知る。Saved の行の左（保存を外す）はモードと関係なく引ける
- **削除ボタンは置かない。** 送信は読むモードの右スワイプと同じ、行の中の隠れた form を払いで送る形に揃え、行の送信の列（`submission_queue.js`）に並べる
- **払いの判定は読むモードと同じ。** 行の幅の `swipe.dismiss_threshold_ratio` まで引いて離すか、`swipe.flick_*` の鍵があれば速い払い。新しい数字の鍵は足さない
- **削除も保存も 1 件 1 コンボ。** 離した時点で数え（応答で数えると、続けて払ってすぐ「読む」に戻したとき列に並んだ分がリザルトから抜ける）、`melody` の次の 1 音を鳴らす。閾値を越えた瞬間の `swipe` の音は処理モードでは鳴らさない（拍が二重になる）。元に戻すと削除・保存とも 1 減る。節目（ADR 0023）も合計で数える
- **リザルトに内訳。** 「n 件 処理した」の下に「削除 a ・ 保存 b」（nao 2026-11-21「保存した件数もリザルトに表示して」）
- **失うもの:** 処理モードの削除と保存がキーボードと VoiceOver からはできない（ADR 0023 でボタンが解いた分が戻る）。一人用で nao は iPhone の指で使う。要るなら、Tab で届いたときだけ出るボタンか VoiceOver のカスタムアクションを足す
- **持ち越し:** 待ちの上限（`swipe.submit_timeout_seconds`）を越えて戻った行を逆向きに払い直すと、先の送信がサーバーに届いていた場合、同じ記事に `dismissed_at` と `bookmarked_at` の両方が入りうる（コンボは同じ記事を 2 件に数えないようにした）。電波が悪く 10 秒を越える場面に限られるので、片方を入れたら他方を消すかはモデルの側で別に決める
