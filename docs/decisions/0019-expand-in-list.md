# ADR 0019: Main の行はタップで下に広げる。要約と「記事に遷移」を一覧の中に出し、Reader へは移らない
日付: 2026-11-08 状態: 採用（#97）。0010・0011 の「Main の『読む』→ Reader」と 0015 の要約の契機の読み方を改める

nao の決定（2026-11-08「一覧画面で記事をタップしたら別画面に遷移するのではなく、その下に３行要約が表示される形式にして、一緒に『記事に遷移』ボタンを作成してほしい。別画面に遷移する時間がもったいない」。#97 の計画を推奨どおり承認）。

- **行のタップは画面を移らない。** 行を覆う「読む」の POST（`expand=1`）に、サーバーは Turbo Stream で行の下の欄（出目の帯・Claude の 3 行要約・「記事に遷移」）を返す。2 度目からは送らずに開閉だけ。一度に広がるのは 1 行（別の行を広げると前の行は畳む）。JS が無いときは今までどおり Reader へ redirect
- **広げた時点で抽選し、`Reading` を作り、要約の Job を積む。** ADR 0015 の「読むと決めた記事」は「広げた記事」と読む。要約済みなら積まない（払うのは 1 回）。広げただけで読まない記事にも 1 回払うが、タップは読むかを決めるための意思表示なので許す
- **Main ではルーレットのモーダルも Jackpot の全画面も出さない。** 待ち時間を削るため。出目は広げた欄の帯に出し、倍率の上がった出目だけ色を変えて現れた瞬間に光らせる（掘り出し物は橙、頂点は金）。`xp.roulette_duration_ms` は Main では使わない（Saved の行のルーレットには残る）
- **「記事に遷移」は元記事を別窓（iPhone のホーム画面アプリではシート）で開く。** 戻ったときの判定（`start` / `advance`、区切り、ステータスの書き直し）は Reader と同じ式で Main に持ち込む。Main では次の記事を継ぎ足さず、その Reading も作らない（読まない記事の要約を払わない）。応答は `advance?from=main` で、区切り・上の 1 行・未読数だけを返す（21b）
- **Reader は残す。** 入口は JS が無いときの POST、Saved の行、Jackpot の「受け取って読む」。撤去するかは使ってから決める
