# ADR 0026: カードの枠は記事の中身で決める。抽選と、Roulette のモーダル・Jackpot 画面をやめる
日付: 2026-11-18 状態: 採用（#134。「決めたこと」は承認済み。「実装の順」の入れ替えは提案で、nao の承認待ち）。0020 の「開いた時に抽選」と 0006 の 2・3、0010 と 0018 と 0019 の Reader の入口、0022 の「鳴らす場所」を改める

nao の決定（2026-11-16「最初から置き換える」。#134 の追記 A〜G を承認）。採点の土台は ADR 0024。

## なぜ
枠の希少度は開いた瞬間の抽選で決まり、記事の中身と関係が無かった。ADR 0024 の採点（6 軸・合計 6〜30）を枠に結び付ける。
採点は外部の API を待つので、開いた瞬間には枠が決まらない。Roulette のモーダル（0.5 秒で出目が止まる）と Jackpot 画面（金なら読む前に全画面）は、抽選がその場で済む前提に乗っていて、そのままでは成り立たない。

## 決めたこと
1. **モーダルと Jackpot 画面を撤去する。** 一覧の外（Saved の未読・宝箱の「もう 1 本だけ」）からの「読む」は、303 で Reader へ直接進む。予告は Reader の帯、頂点の全画面は完読の区切りの開封（既存）に一本化する。docs/screens/roulette.md と jackpot.md は廃止
2. **段は 4 つ**: ノーマル / レア / S レア / SS レア（`readings.tier` は `normal / rare / s_rare / ss_rare`）。頂点の演出（金の全画面とファンファーレ）は SS レアに付く
3. **yml `cards.rarities` は確率でなく合計点の下限（`min_total`）を持つ。** 出る頻度は記事の中身しだいで、約束できる確率は無くなる
4. **枠は判定が届いた時に `readings.tier` へ書き、以後は動かさない。** 届くまで tier は空（判定中）。境界を後で変えても手に入れたカードは変わらず、付け直すのは `bin/rails judgments:regrade` だけ（判定済みの記事のカードを今の境界の段にする）。判定を積めない環境（yml の節か API キーが無い）では待っても届かないので、開いた時に一番下の段にする
5. **帯のリールは判定を待って止まる。** 待つ間は段を回し続け、Job が枠を決めた時に Turbo Stream（要約と同じ購読）で止まる帯を配る。接続の前や切断中に配られた分は、接続が戻った時に帯が取り直す（`GET /readings/:id/tier`）。届く前に記事へ進んでもよい。判定中のまま完読したら、カードは段の名を付けず破線の枠でめくれ、届いた時に見出しとカードを差し替える
6. **判定できない記事（本文なし・読めない応答・再試行の使い切り・予算切れ・4xx の拒否）はノーマルに決める。** 帯と区切りに「判定できず」と添える。待たせ続けない
7. **過去のカードは採点し直して付け替える。** migration が common → ノーマル、jackpot → SS レアに読み替え（rare はそのまま）、`judgments:backfill` で採点してから `judgments:regrade` で中身の点の枠にする。判定できないものは読み替えのまま残る

## 実装の順
1 を先に入れ、2〜7 を後に入れる。1 だけが入った版では抽選がまだ生きている。その間の Reader の帯は、抽選した直後に開いた 1 本目だけリールを回して段の音を鳴らす（開き直しと継ぎ足した記事では回さない）。
計画（#134 の追記）は 2〜7 を先に書いていたが、モーダルと Jackpot 画面が残ったまま tier を空にすると、出目の位置を tier から引くモーダルが壊れる。順を入れ替えれば、どの版も通して動く。

## 採らなかった案
- **モーダルを残し、判定を待って止める**: 判定は数秒かかりうる。閉じられないモーダルで待たせるより、読みながら帯で待つほうが読む流れを止めない
- **併用（抽選の枠と内容の格を別の札にする）**: nao が「最初から置き換える」を選んだ。札が二つあると、どちらが報酬なのかが薄まる
- **判定が届くまで抽選の枠を仮に見せる**: 届いた時に枠が下がることがあり、手に入れたものを取り上げる体験になる

## 承知している弱み
- SS レアの頻度を決められない。採点は確率の重み付けで中央に寄りやすく、28 点は滅多に出ない恐れがある。過去カードの分布を見て閾値を見直す
- 記事本文に「満点を付けよ」と書かれると枠が水増しされうる。被害は演出だけで、秘密や操作には届かないので受け入れる（ADR 0024、SECURITY.md）
- 抽選で金だったカードが、採点し直しで下がることがある
- 予算切れや拒否でノーマルに決まった記事は、後で判定が届いても枠は動かない（決めたこと 4）。直すのは `judgments:regrade`
- 判定中のまま完読した後に頂点の段が届いても、全画面の開封と見せ場の「SS レアカード！」は出ない。読み終えた後から画面を覆うより、カードの枠が替わるだけにとどめた
- 取り直しで追いつくのは帯だけ。接続が切れている間に届いた区切りの見出しとカードは、再読込まで判定中のまま
- 版を戻すときは `db:rollback` も要る（旧版は 3 段の名前しか知らず、空の tier を持てない）。戻すと S レアはレアに、判定中は通常になる
