# ADR 0034: 週のレポートの画像は端末の Canvas で描き、Web Share API で共有シートに渡す
日付: 2026-11-23 状態: 提案（#173。nao の指示「続きをスタック PR で作成して」で 34c として実装し、PR で判断を仰ぐ）。weekly.md 未決 1 を閉じる

## 決めたこと
- **画像は端末で描く。** Stimulus の `weekly-share` コントローラが `<canvas>`（1080×1350、縦長の SNS 向け比率）に描き、PNG にする。外部 JS は使わない（AGENTS.md）
- **描く材料はサーバーが data 属性に JSON で渡す（`WeeklyHelper#weekly_share_card`）。** 文言（「先週比 +40%（10 本）」「Claude のひとこと ・ 11/9 – 11/15 の週」など）は画面と同じ helper で組み立て、JS は配置と描画だけを持つ。画面の DOM は写さない
- **共有は Web Share API（`navigator.share({ files })`）。** iPhone のホーム画面アプリでも Safari と同じく共有シートが開く。`navigator.canShare({ files })` が偽の端末（デスクトップの一部）では PNG を保存させる。共有シートを閉じただけ（`AbortError`）は失敗にしない
- **フォントは端末のもの。** iPhone ではヒラギノ、無ければ Noto Sans JP、最後は sans-serif。Web フォントは読み込まない
- **ひとことは 5 行（120 字で収まる量）まで描き、それを超えた分は最後の行を「…」で終える。** 句読点と閉じ括弧は行頭に送らず、英数字の語は途中で折らない。長いフィード名は名前だけを詰め、本数は残す
- **画像はボタンを押す前（画面を開いたとき）に描いておく。** iOS は押した操作の中でしか共有シートを開かず、押してから描くと待ちの間に操作の扱いが切れうる。それでも開けなかったとき（`NotAllowedError`）は、作った PNG を保存させる

## 見送った案
- **サーバーで SVG を描いて PNG にする**: Docker イメージに描画ライブラリ（librsvg・ImageMagick・libvips のどれか）と日本語フォント（数十 MB）が要り、1GB の Lightsail で 1 枚ごとに描画の負荷がかかる。サーバーに置けば OGP 画像にも使えるが、一人用で公開ページは無い
- **画面の DOM を画像にするライブラリ（html-to-image 系）**: 外部 JS の持ち込みにあたる。Tailwind の効き方やスクロール位置まで写り、崩れの原因が増える
- **画面をスクリーンショットしてもらう**: 手で切り抜く手間が残り、タブバーなどが写り込む

## 影響
- 画像の見た目は spec/system で寸法（1080×1350）と型（PNG）とファイル名だけを確かめる。配置の崩れは `bin/screens` の絵と手元の書き出しで目で見る
- 共有シートの中身（送り先のアプリ）は端末に任せる。サーバーは画像を受け取らず、保存もしない
