# ADR 0010: 記事はアプリ内で本文を描き、読了は末尾までのスクロールで判定する
日付: 2026-11-04 状態: 採用（#43）

nao の決定（2026-11-03「現在の main を動かしたらイメージと違った。情報元に遷移せずに無限スクロールで記事を読みたい」、2026-11-04 に #43 の計画を推奨どおり承認）。docs/SPEC.md の「記事は PWA 内のブラウザシートで開く。本文をアプリ内に描画しない」と、read_done.md 未決 5 の決定（戻りを visibilitychange / pageshow で拾う）を覆す。

- **本文はアプリ内で描く。** 材料は `articles.content`（readability で抜いた HTML）。描く直前に、取得時と同じ許可リスト（`ArticleContentFetcher::TAGS` / `ATTRIBUTES`）で消毒し直す。DB の中身を信用しない。取れなかった記事は 3 行要約と「元記事で読む」で代わりにする。画像は元サイトから端末が直接読む（プロキシしない）
- **読了の判定は「記事が現れた時刻」と「末尾が画面に入った時刻」の差。** 式（`read.complete_after_seconds` 以上で完読）と `Reading#return!` は変えない。変わるのは「戻った時刻」の取り方だけ。時刻はどちらもサーバーの時計
- **無限スクロールは Turbo Stream。** 末尾の form を IntersectionObserver が 1 回だけ送り、応答が判定の区切りと次の記事を継ぎ足す。SPA 化しない（ADR 0001）。最初から末尾が見えている記事は自動で送らない（読む前に未完と判定されるため）
- **次の記事の行（抽選と開いた時刻）は判定の POST の中で作る。** GET の描画で書き込まない。順は Main と同じ新しい順で、押した記事より古い未読へだけ進む（未完で区切った記事を同じ流れに二度出さない）
- **2 本目以降の抽選結果は記事の頭の「出目」の帯で見せる。** ルーレットのモーダルは Main の「読む」のときだけ
- **元サイトへ出て戻る経路は撤去する**（5c-2）。iPhone の standalone で戻りの合図が来るか（#40）は問わなくてよくなる
