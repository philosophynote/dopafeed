# ADR 0027: 削除済みの記事は 1 日、未読の記事は取得から 3 日で物理削除し、消した記事の目印を残す
日付: 2026-11-19 状態: 採用（#144）。ADR 0012 の `dismissed_at` を残すことと、0014 の購読の削除は変えない

nao の決定（2026-11-19「記事が溜まっていくので削除済みの記事は１日後に自動的に削除したい。また、未読の記事も３日後に削除したい」。#144 の計画の決めどころ 3 つを推奨どおり「全て承認」）。

- **消すのは 2 区分。** 削除済み（`dismissed_at` から `retention.dismissed_days` 日）と未読（`Article.unread`、取得の `created_at` から `retention.unread_days` 日）。境の時刻ちょうどは消す側
- **未読の起点は取得日時。** 公開日時にすると、フィードを登録した直後の過去記事（数週間前の公開）が見る前にまとめて消える。公開日時の無い記事・日付の狂ったフィードでも同じに効く
- **保存（`bookmarked_at` / `liked_at`）と完読（`Reading.completed`。図鑑のカード）は日数を過ぎても消さない。** 削除済みでも、保存が付いている・Reader で読み終えた記事は残す（ADR 0012 の 4 項）。抜き出してから消すまでに保存・完読が付いたら残るよう、トランザクションの中で条件を組み直して引き直す（`in_batches` の batch は `rewhere(id:)` で完読の除外を落とすので、batch をそのまま使わない）
- **開いたが未完の記事も未読として消し、未完の `Reading` も一緒に消す。ただし前の読書日の始まりから開いた・戻った記事は残す。** 読んでいる途中の記事が消えると戻ったときに完読を記録できず、今日の連続を切っている未完の行が消えると「n 連続」とフィーバーが伸びる（`Combo` は今日戻った行を新しい順に完読が続く間だけ数える）。図鑑・今日のゴール・連続日数は完読だけから数えるので動かない。動くのは NEW RECORD の比べ相手（過去の日ごとの最長連続）で、消えた未完の所で連続がつながり、長く数え直されることがある。残すと、開いて止めた記事が読むか削除するまで一覧に居続ける
- **判定（`article_judgments`）は外部キーの cascade で記事と一緒に消える。** 完読の記事は残るので、カードの判定とレーダーは残る
- **消した記事の目印を `purged_articles` に残す。** 取り込みは「同じ `[feed_id, guid]` か `url` の記事があるか」で重複を弾くので、記事だけ消すと、フィードに載り続けている項目が次の取得で新着の未読として戻る。目印は `feed_id`・`guid`・`url`・`reason`（dismissed / unread）・`purged_at` で、記事と同じ二本立ての一意索引を持ち、記事を消すのと同じトランザクションで書く。`FeedFetcher` は目印のある項目を飛ばす
- **目印は消さない。** フィードから古い項目が落ちる時期はサイト次第で、期限を切ると生き返りが起きる。1 行は数百バイトで、1 日 100 本でも年に十数 MB に届かない。重くなったら期限の鍵を足す
- **目印は購読と一緒に消える**（外部キーの `on_delete: :cascade`）。購読し直せば記事を取り直す（ADR 0014 と同じ）
- **`reason` を残すのは、後の学習（ADR 0012 の「材料」）でフィードごとの消した数を数えられるようにするため。** 見出しと単語は残さないので、単語の重みには使えない
- **日数は `config/dopamine.yml` の `retention`。鍵が無い区分は消さない。** 戻せない操作なので、書き漏れで消えるより残る方を選ぶ
- **production の Solid Queue で毎時（`config/recurring.yml` の `purge_articles`）。** 消えるまでの遅れは最大 1 時間。`in_batches` で 1 バッチ 1 トランザクションにし、書き込みのロックを長く握らない。手で回すのは `bin/rails articles:purge`
- **SQLite のファイルは小さくならない。** 空いたページを使い回して伸びが止まる。VACUUM はしない
- **誤って消えたら** Litestream の時刻指定の復元（runbook 1-c、72 時間まで）で戻す
