# ADR 0011: 記事は元サイトのままアプリ内ブラウザで開き、読了は開いてから戻るまでの時間で判定する
日付: 2026-11-04 状態: 採用（#50）

nao の決定（2026-11-04、#43 のマージ後に main を手元で試して「はっきり言って読みづらい。アプリ内ブラウザのように読みたい」。決定札で「元サイトをシートで開く」を選び、#50 の計画を推奨どおり承認）。ADR 0010 のうち「本文をアプリ内で描く」と「末尾までのスクロールで判定する」を覆す。Reader の枠（カードの流れ・区切り・次の記事の継ぎ足し・`returned_at` の読み替え）は 0010 のまま残す。

- **本文はアプリ内に描かない。** readability で抜いた HTML は、元サイトの組版（コードの色・図・埋め込み）を失って読みづらかった。カードには見出し・出目の帯・Claude の 3 行要約と「記事を開く」だけを出す。本文の取得（`FetchArticleContentJob`・`articles.content`）は要約の材料として残す
- **元サイトは `target="_blank"` のリンクで開く。** iPhone のホーム画面アプリ（standalone）ではアプリの外の URL は下から上がるアプリ内ブラウザ（シート）で開く。Mac などのブラウザでは別タブになる。ルーレットが止まった瞬間に自動で開くことはしない。タップ無しで新しい窓を開くと、iOS もデスクトップのブラウザもポップアップとして止めるため、1 本ごとに「記事を開く」を 1 回押してもらう
- **埋め込み（iframe）は採らない。** 多くのサイトが `X-Frame-Options` / CSP の `frame-ancestors` で埋め込みを断る。断らなくても、別オリジンの中のスクロールはアプリから見えない。元ページを自分のサーバーで中継する手も、スクリプトと Cookie の扱いが危うく、見た目も崩れるので採らない
- **読了の判定は「記事を開く」を押した時刻と、アプリに戻った時刻の差。** 式（`read.complete_after_seconds` 以上で完読）と `Reading#return!` は変えない。開いた時刻は `POST /readings/:id/start`（`Reading#start!`、判定前の行だけ）で記録し直す。カードが継ぎ足されてから開くまでの、要約を眺めていた時間は滞在に入れない。時刻はどちらもサーバーの時計
- **戻りの合図は `visibilitychange` と `focus`。拾えないときは手で押す。** 開いた後に Reader が隠れるか focus を失い、その後に見えるか focus が戻ったら「読み終えた」を 1 回だけ送る（Stimulus `sheet`）。iPhone のシートを閉じたときにこの合図が来るかは実機で確かめていない（#40 で問うたまま答えが出ていない）。来なくても記録できるよう、「読み終えた」のボタンを「記事を開く」の後に出す。開く前は隠す。開かずに押して XP を取らせないため
- **開いた時刻の記録は投げっぱなし。** `start` が届かないか、すぐ戻って `advance` に追い越されると、滞在は行を作った時刻から数えられ長めに出る。読むのを止めるほどの害ではないので、待ち合わせはしない
- **シート越しでは末尾まで読んだかは分からない。** 判定は開いていた時間だけで決まる。開いたまま放置すれば完読になる穴は 0010 より広い。`read.max_dwell_seconds`（#41）で塞ぐ

追記 2026-11-05（iPhone 実機で合図を確かめた）: 出た合図に `blur` は使わず、`visibilitychange` の hidden だけにする。戻りは hidden の後の visible か focus。ホーム画面アプリ（「Webアプリとして開く」をオン）で合図を並べると、「記事を開く」を押した瞬間に blur → focus が続けて来て（シートが開く前）、その後に hidden、シートの間は画面ごと止まり（タイマーも動かない）、閉じると visible → focus だった。blur を使っていたときは押した瞬間の focus を戻りと取り違え、滞在 0 秒で判定していた。デスクトップで元の画面が隠れない別窓に開いたときは自動では送らず、「読み終えた」の手押しに頼る
