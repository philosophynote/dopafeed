# Controller の確認項目

節番号は『コードレビューで学ぶ Ruby on Rails 第三版』に対応する。`config/routes.rb`、継承・認証の設定、呼び出し元のフォームや Turbo 応答を同じ版で追う。

- HTTP メソッドと URL が操作の意味に合うか。`resources` の基本アクション、ID を受け取らない `resource`、業務上の操作を表すリソースのうち、呼び出し元が分かりやすい形を選べているか（§3.1、§3.8、§3.12、§3.14）。
- ネストする場合、親子の関係が取得条件にも使われ、ルートの `module` と対応するコントローラーを追えるか（§3.7）。
- 権限が異なる入口に名前空間を設ける場合、基底コントローラーと継承から共通の認証・認可が漏れなく適用されるか（§3.3、§3.11）。
- コントローラーのデータ操作や業務ルールがモデル・サービスと重複していないか。リクエストの解析、操作の委譲、レスポンスの責務が追えるか（§3.2）。
- セッションに最小限の情報を置いているか。認証に使うインスタンスと更新対象を共有する場合、保存が失敗してもレイアウトやレスポンスに未保存の値が漏れないか（§3.4、§3.5）。
- 一覧の並びを明示し、同じ時刻・スコアの要素が同時にあっても一意なタイブレーカーで順序とページ境界が安定するか（§3.6）。
- ID からの取得を、許可した操作対象や親リソースに絞っているか。Strong Parameters の許可とレコード自体の認可をそれぞれ確認する（§3.9）。
- 保存とメールや通知の成功条件を追う。保存が失敗した場合や同じ操作を再送した場合に配信されるかを調べる（§3.10）。
- 削除に失敗したときに成功レスポンスや通知が返らないか。`destroy!` と例外処理、または `destroy` の戻り値を扱う失敗分岐を確認する（§3.13）。
