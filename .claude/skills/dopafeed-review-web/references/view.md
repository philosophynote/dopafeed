# View の確認項目

節番号は『コードレビューで学ぶ Ruby on Rails 第三版』に対応する。Dopafeed の ERB、Tailwind、Turbo、Stimulus の既存の契約と画面仕様を確認する。

- ERB に集計・状態更新・複雑な業務判断が入り、画面ごとに結果がずれないか。表示に固有の処理は既存のヘルパーやパーシャルで共有できるか（§2.1）。
- レイアウトに異なるページ群の分岐が集まり、共通枠や適用条件が分かりにくくなっていないか（§2.2）。
- パーシャルや表示部品のルート要素が、親のレイアウトと Turbo 置換の単位に合っているか。外側の間隔は配置する側で決められるか（§2.3、§2.8）。
- 一時的に使えない操作の状態と理由が分かるか。表示の有無とは独立に HTTP 側の認可も確かめる（§2.4）。
- ビューを移動・共有したときに翻訳キーが解決されるか。日付と時刻の表示は `I18n.l` と既存の書式・タイムゾーンを確認する（§2.5、§2.12）。
- Tailwind のビルドがクラス名を検出できるか。文字列を組み立てる箇所では、対応する完全なクラス名やビルド設定を確認する（§2.6）。
- リンクの文言から行き先が分かり、ボタンや見出しなどが意味に合った要素になっているか。読み上げとキーボードで操作できるか（§2.7、§2.9）。
- Stimulus が `this.element` や targets を使い、同じコントローラーが複数あっても作用範囲が保たれるか。接続・切断を繰り返したときのイベントとタイマーを確認する（§2.10）。
- GET の遷移、状態を変えるフォーム、クライアント内の操作で要素を使い分けているか。更新では `button_to` や既存フォームの HTTP メソッドと CSRF を確かめる（§2.11）。
- Turbo の frame、stream、対象 DOM で識別子が一致し、同時に表示する記事やカード間で衝突しないか。新規の固定 ID には `turbo_` など、用途が分かって検索しやすい名前を検討する（§2.13）。
